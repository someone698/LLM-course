# 人民日报语料 n-gram 语言模型：清洗、KenLM 训练与续写

1998 年 1 月《人民日报》切分标注语料上的词级 n-gram 实验（课程作业 P125）。内容包括：

- 语料清洗（去文章编号 / 去词性标签 / 修嵌套专名标注的括号）与文章级 train/valid/test 划分
- 在**没有 Boost、没有 sudo** 的机器上构建 KenLM 的 `lmplz`，训练 1–5 阶模型
- 困惑度、OOV、"平均实际用到的阶数"，以及数据稀疏度的直接测量
- 固定前缀续写：阶数 × 解码策略 × 温度

**本仓库不含语料与模型文件**（体积原因），下载与重新生成方式见文末。

## 流水线

```

        │
        │  01_clean.py   去文章编号、去词性标签、拆嵌套专名标注的括号、文章级划分
        ▼
data/renmin.clean.txt        纯词序列，一行一篇（全量 19,484 行 / 1,121,444 词）
data/renmin.tagged.txt       保留标签的对照版
data/split/{train,valid,test}.txt   19,103 / 184 / 197 篇
        │
        │  02_train.sh    KenLM lmplz，1..5 阶，计时 + 记 n-gram 条数
        ▼
out/models/renmin.Ngram.{arpa,bin}
out/train_bench.tsv          训练耗时/体积/阶数规模对比表
out/logs/lmplz.N.stderr      lmplz 的训练过程输出
        │
        ├─ 03_generate.py   从前缀续写（greedy / 采样 × 温度）
        ├─ 04_eval.py       验证集/测试集困惑度 + OOV 率
        ├─ 05_sparsity.py   数据稀疏度测量
        └─ 06_uncleaned_control.py   对照实验：不清理会怎样

data/split_tagged/{train,valid,test}.txt   同一套划分套在 tagged 版上（06 用）
out/models_tagged/                         06 训出的"不清理"版模型
out/uncleaned_control.md                   06 的对照报告
```

## 运行

```bash
# 0) 语料（下载命令见文末「语料」一节，落到 data/renmin.raw.txt）

# 1) Python 依赖：只需 kenlm 的查询接口（PyPI 有预编译 wheel，无需 Boost）
python3 -m venv .venv && .venv/bin/pip install kenlm

# 2) 准备 KenLM 的 lmplz（关键：PyPI 的 kenlm 包只有 Python 查询接口，没有 lmplz）
git clone https://github.com/kpu/kenlm.git tools/kenlm
bash tools/build_lmplz.sh          # 得到 tools/bin/{lmplz,build_binary}

# 3) 清洗 + 划分
python3 scripts/01_clean.py

# 4) 训练（默认 1..5 阶，约 1 秒/阶）
bash scripts/02_train.sh
#   或指定：ORDERS="1 2 3 4 5 6" LMPLZ=/path/to/lmplz bash scripts/02_train.sh

# 5) 续写
.venv/bin/python scripts/03_generate.py --orders 2 3 4 5 --gen 20

# 6) 困惑度 + 平均实际阶数
.venv/bin/python scripts/04_eval.py --orders 2 3 4 5

# 7) 数据稀疏测量
.venv/bin/python scripts/05_sparsity.py

# 8) 对照实验：不清理会怎样（用 02/03 两个脚本，只换输入与输出目录）
.venv/bin/python scripts/06_uncleaned_control.py
```

### 关于 KenLM 的编译：官方 cmake 在本机走不通

`tools/build_lmplz.sh` 不是官方构建路径，是为了**在没有 Boost、没有 sudo 的机器上**
把 lmplz 编出来。取舍如下：

- 官方 `CMakeLists.txt:101` 强制 `find_package(Boost REQUIRED COMPONENTS program_options
  system thread unit_test_framework)`。全仓排查后确认 Boost 只出现在三处：
  各 `*_main.cc` 的命令行解析、`lm/common/size_option.cc`（program_options 的包装）、
  以及单元测试。
- **训练引擎 `lm/builder/{corpus_count,adjust_counts,initial_probabilities,output,pipeline}.cc`
  零 Boost 依赖。** 所以 `tools/boost_shim/` 提供 15 个垫片头文件，
  `tools/lmplz_main_noboost.cc` 逐段移植官方 `lm/builder/lmplz_main.cc`、
  只把手写参数解析换掉了 `boost::program_options`。
- `tools/kenlm/` 保持与上游 `kpu/kenlm@4cb443e` **逐字节相同**（`git status` 为空），
  改动的只有仓库外的两个文件。**训练算法本身是原版 modified Kneser-Ney，
  未作任何修改。**
- `build_binary` 用的是 getopt，本来就无 Boost，直接编。它被编出来是为了量化
  二进制格式的压缩效果（见下表），不参与训练。

## 清洗规则与理由

原始语料每行一篇，形如：

```
19980101-01-001-001/m  迈向/v  充满/v  希望/n  的/u  新/a  世纪/n  ——/w ...
└─ 文章编号/词性        └─ 词/词性 ...   （词与标签之间用 / 连接，用空格分词）
```

清掉四类东西：

| # | 清掉 | 量 | 不清会怎样 |
|---|---|---|---|
| 1 | 行首文章编号 `19980101-01-001-001/m` | 19,484 个（19,483 个不同，有一个重复） | 每篇开头都是一个几乎独一无二的 token；出现的 n-gram 组合各只见过一次，条件概率退化成均匀分布，白占词表 |
| 2 | 词性标签 `迈向/v` → `迈向` | 覆盖全部 1,121,444 词 | 模型学的是"词+词性的拼接串"。生成时会直接吐出 `在/p 阳光/n 明媚/a`——因为对模型来说 `/p` 和 `/n` 就是词的一部分。语素族 `摄/Vg`（`Ng/Vg/Tg/Ag/Dg/Rg/Bg` 共 7,289 处）是标记集对**构词成分**的正式标记、不是错误，但同样要拆 |
| 3 | 兼类词的词性分裂 | 5,477 个兼类词（占词型 9.90%，但覆盖 39.12% 的 token 位置）→ 多出 6,721 个词表项 | `高` 分裂成 8 个 token：`高/a` 877、`高/nr` 112、`高/ad` 24、`高/v` 20、`高/an` 9、`高/j` `高/Ng` `高/d` 各 1。**8 个形式之间没有共享统计的通道**——KN 的回退是沿上下文丢最左边的词，从不跨标签转移折扣，所以 `高/a` 学到的折扣帮不到 `高/nr` |
| 4 | 嵌套专名标注的括号 `[中央/n 人民/n 广播/vn 电台/n]nt` | 开、闭括号各 9,238 个 | 开括号粘在词左（`[中央/n`）、闭括号粘在标签右（`电台/n]nt`）。**只拆一半会把 `[中央` 留成独立词条**，与正文里的 `中央` 裂成两个词——首版正是这么漏的，补拆后词表反而少了 1,164 类 |

实测词表：清洗后 **55,310** 类，不清理 **62,031** 类，膨胀 **1.122×**；
其中 5,477 个兼类词贡献了全部 6,721 个额外类型（文章编号未计入任一侧词表）。

**对照实测**（`06_uncleaned_control.py` → `out/uncleaned_control.md`）：
上表"不清会怎样"一列原先只有机制推断——`renmin.tagged.txt` 生成之后从未真的训练过。
现在补上了这条对照：唯一变量是 token 粒度，两版语料由 `01_clean.py` 同一次循环产出、
逐行对齐（脚本内含逐 token 校验），**文章划分与 token 位置数完全相同**。摘要：

- 量化代价**方向一致，但幅度不大**：5-gram 的 OOV 率 2.36% → 2.72%，
  平均实际阶数 2.145 → 2.107，5-gram 相异率 96.19% → 96.35%。
- 定性代价是**决定性的**：不清理的模型每个 token 都带 `/词性`，输出格式本身就错了。
- 文章编号造成的词表膨胀（×1.352，19,483 个编号里 19,482 个只出现一次）其实**比词性标签（×1.122）更大**。
- ⚠️ **困惑度不可比，不要拿它下结论**：tagged 模型预测 (词, 词性) 联合分布、
  clean 模型预测词的边缘分布，而 H(词,词性) ≥ H(词) 恒成立——
  tagged 模型无论训练得多好这个数都必然更大。

**标签的出处**：这份语料是北京大学计算语言学研究所加工的人工标注语料（1998 年 1 月，
约 112 万词），标记集即《现代汉语语料库词类标记集》——后来国标 GB/T 20532 的同源前身。
实测 44 种 = 26 个基本类 + 专名子类（`nr/ns/nt/nz/nx`）+ 动形句法子类（`vn/vd/ad/an`）
+ 语素族（`Ng/Vg/Tg/Ag/Dg/Rg/Bg/Mg/Yg`）。**我们只做"拆"，没有标注过任何东西**。

**一句话**：tag 是给人看的语法注释，不是语言本身。语言模型要学的是"词之后接什么词"，
把 tag 混进 token 里，等于让模型去预测语法标注员的工作，而不是预测语言。

## 结果

语料：1998-01 人民日报，文章级划分 train/valid/test = 19,103 / 184 / 197 篇。

### 1. 训练代价随阶数增长

| 阶数 | 训练耗时 | ARPA | 二进制 | 1-gram | 2-gram | 3-gram | 4-gram | 5-gram |
|---|---|---|---|---|---|---|---|---|
| 1 | 0.16 s | 1.0 MB | — | 54,800 | | | | |
| 2 | 0.38 s | 12.0 MB | 9.7 MB | 54,800 | 457,780 | | | |
| 3 | 0.62 s | 41.1 MB | 27.0 MB | 54,800 | 457,780 | 857,178 | | |
| 4 | 0.90 s | 85.0 MB | 48.9 MB | 54,800 | 457,780 | 857,178 | 991,895 | |
| 5 | 1.10 s | 136.8 MB | 72.1 MB | 54,800 | 457,780 | 857,178 | 991,895 | 1,019,003 |

三件事：

- 低阶 n-gram 表在所有高阶模型里原样保留（5-gram 模型的前 4 阶条数与 4-gram 模型逐条相同）。
- **体积增长远快于耗时增长**：ARPA 从 12.0 MB 涨到 136.8 MB（11 倍），训练耗时只从
  0.38 s 涨到 1.10 s（2.9 倍）。1.1 M 词这个量级上，训练还没到算力瓶颈，
  瓶颈是输出规模。真实语料上这条曲线会反过来——阶数越高，计数和排序的
  临时数据越大，内存和磁盘 IO 才是主要成本。
- `build_binary` 把 ARPA 压到约一半：二进制格式里词存的是整数 ID 而不是 UTF-8 串。

1-gram 没有二进制：KenLM 的二进制格式和查询引擎**硬性要求 ≥2 阶**
（`This ngram implementation assumes at least a bigram model`），
1 阶 ARPA 连 `kenlm.Model` 都加载不了。

### 2. 困惑度，以及"名义阶数"与"实际用上的阶数"

| 阶数 | valid PPL | test PPL | 平均实际阶数 (test) |
|---|---|---|---|
| 2 | 525.86 | 511.96 | 1.686 |
| 3 | 420.24 | 389.20 | 1.976 |
| 4 | 408.68 | 377.89 | 2.091 |
| 5 | 407.14 | 376.47 | 2.145 |

「平均实际阶数」取自 `kenlm.Model.full_scores()` 返回的第二个字段——**预测每个词时
模型真正用上了多长的上下文**（回退后的实际阶数）。5-gram 模型这个数是 **2.145**：
名义上 5 阶，实际平均只用得上 2 阶多一点。

边际收益的衰减同样明显：2→3 阶困惑度降 123，3→4 降 11，**4→5 只降 1.4**（0.4%），
而这一阶的代价是训练时间 +22%、模型体积 +61%。

### 3. 为什么回退：数据稀疏的直接测量

| 阶数 k | 训练集 k-gram 位置数 | 相异 k-gram 数 | 相异率 | 测试集未见上下文 |
|---|---|---|---|---|
| 1 | 1,099,582 | 54,797 | 4.98% | 2.40% |
| 2 | 1,080,479 | 450,544 | 41.70% | 32.03% |
| 3 | 1,061,522 | 836,216 | 78.78% | 71.28% |
| 4 | 1,043,182 | 962,118 | 92.23% | 88.54% |
| 5 | 1,025,191 | 986,165 | **96.19%** | **94.48%** |

训练集里 96.2% 的 5-gram 只出现过一次；测试集里 **94.48% 的 5 元上下文在训练集
从未出现**——这些位置模型别无选择，只能回退。

**两条独立路径互相印证**：若「用到 k 阶」的概率 ≈ 「k 元上下文出现过」的概率，
则 E[阶数] ≈ Σ(1 − 未见率) = 0.976 + 0.680 + 0.287 + 0.115 + 0.055 = **2.11**；
而第 2 节中 KenLM 自己报的实测值是 **2.145**。差 1.5%，一致。

这组数字就是"n 不能无限增大"的答案：加大 n 不是让模型看得更远，
只是在给一个训练集里几乎不存在的上下文建表。**要让它看得更远，缺的是数据，不是阶数。**

### 4. 续写：同一个前缀，不同阶数与温度

前缀 `在阳光明媚的五月，我们学校胜利召开了`。

| 设置 | 续写 |
|---|---|
| 2-gram greedy | …召开了**，在北京１月１３日电（记者王磊）、“菜篮子”，在北京１月１３日** |
| 3-gram greedy | …召开了**第十五次全国代表大会，高举邓小平理论伟大旗帜，把建设有中国特色社会主义的伟大旗帜，** |
| 4-gram greedy | …召开了**。”，这是一种，其中包括：一是在生产上，主要是由** |
| 5-gram greedy | …召开了**。”，这是一种，其中包括《邓小平同志的遗志，把建设有** |
| 2-gram T=1.0 | …召开了**解决具体都同志为一钱不值却彩旗猎猎、青岛红晕我国患者状态的，数字：社会的** |
| 3-gram T=1.0 | …召开了**这个般的作品。所在单位建房、朝鲜地花鼓。五年计划伙伴的，还是不干，** |
| 4-gram T=1.0 | …召开了**上海国立局面，战胜七点三亿立方米做的表现仲达针对赞语或、，１５６７和平结束）** |
| 5-gram T=1.0 | …召开了**上海国立局面，战胜七点三亿立方米做的表现仲达针对赞语或、，１５６７和平结束）**（与 4-gram 逐字相同） |

- **2-gram greedy 直接掉进循环**：第 17–20 步 `在 北京 １月 １３日` 的 log10 P
  （−1.6372 / −1.7829 / −0.4878 / −1.3478）与第 2–5 步**逐位相同**——模型绕回了同一个环。
  2-gram 的状态只有一个词，一旦走到自环概率最高的位置就出不来。这是 n-gram 的经典退化。
- **3-gram greedy 最"像话"**，因为它整句复述了训练集里真实存在的句子
  （十五大报告相关报道）。看逐步 log10 P 也印证：`邓小平理论` −0.0309、`旗帜` −0.0116，
  概率接近 1，说明模型是在背，不是在生成。
- **4-gram/5-gram greedy 反而更差**。因为 4 阶以上的上下文在训练集里太稀疏
  （见第 3 节），greedy 在最高阶找不到可靠延续时回退，接出来的片段跨度更大、
  语义断裂更明显。
- **温度 T=1.5 时 4-gram 与 5-gram 输出完全相同**——高温把概率分布抹平，
  采样几乎只由低阶回退分布决定，此时模型的"高阶"信息已经被淹没了。
- T=0.5 贴近 greedy、T=1.5 开始出噪声词，符合预期：温度只是调节分布的锐度，
  **它不能创造模型没学到的知识**。

## 语料

1998 年 1 月《人民日报》切分标注语料（PFR 语料库公开部分）。**本仓库不附带语料文件**，
请自行下载后放到 `data/renmin.raw.txt`：

```bash
mkdir -p data
curl -L -o /tmp/pd1998.zip \
  https://github.com/chenhui-bupt/PeopleDaily1998/raw/master/199801.zip
unzip -p /tmp/pd1998.zip '199801/199801.txt' > data/renmin.raw.txt
```

> ⚠️ **上面这条命令下到的，不是本文所有数字跑的那一版文件。**
> 同一份 1998 年 1 月语料有**两个标注修订版**在流传，本仓库的数字来自 A 版，
> GitHub 镜像里的 `199801.zip` 是 B 版。两版的文章数、文章编号逐个相同，
> 但**16.6%（3,230 / 19,484）的行标注不一致**：11.96% 的行分词相同而词性不同
> （`南北/f` 对 `南北/n`、`局部/n` 对 `局部/b`、`独立自主/i` 对 `独立自主/l`），
> 4.61% 的行连**分词本身**都不同。
>
> | | A 版（本文数字的来源） | B 版（GitHub 镜像 `199801.zip`） |
> |---|---|---|
> | sha256 | `ef95b454656b9580a28753245317b2d8f1088269b44c6015308d25c90647d3b0` | `41760f40739b0f301ab29e99ab14565e7cd4b06128eb3a6ac18bce277a6075a8` |
> | 字节数 | 10,648,033 | 10,666,468 |
> | 行尾 / 物理行 / 空行 | LF / 23,064 / 3,580 | CRLF / 22,564 / 3,080 |
> | token 总数 | 1,121,444 | 1,120,721 |
> | 清洗后词表 | **55,310** | 55,414 |
> | 不清理词表 | **62,031**（×1.122） | 63,128（×1.139） |
> | 兼类词 / 额外类型 | **5,477 / 6,721** | 6,025 / 7,714 |
> | 独有标签 | `na` `vvn` | `l/%` `q/m`（脏标签） |
>
> **结论不受影响**（膨胀都是 ×1.1 量级、兼类词都是个位数百分比），但具体数字会变：
> 用 B 版跑，正文表格里的 55,310 / 62,031 / 5,477 要换成 55,414 / 63,128 / 6,025。
> 两版都是 19,484 个非空行、19,483 个不同文章编号。

`01_clean.py` 按"行首是否为 `日期-版次-版面-序号/m`"识别文章边界，不写死月份，
同一归档里的 `199802.txt` 等可直接替换复用，脚本不用改。
